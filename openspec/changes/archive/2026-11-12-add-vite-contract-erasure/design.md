# Design

## Context

`prepareSource` уже строит TypeScript Program и возвращает IR и SourceFile; `verify.ts` совмещает отчёт и CLI. `sourceGraph` распознаёт API по исходному символу и абсолютному пути, разрешает только относительные модули. Runtime для тестов использует снимок, но его инструментация не подходит для production. В репозитории установлен Vite 8 через Vitest; пользователь выбрал Vite первым сборщиком.

## Goals / Non-Goals

**Goals:** общий verifier без зависимости от Vite, точное удаление из исходного снимка, пригодный для локальной установки JS-пакет, реальная проверка интеграции Vite 8.

**Non-Goals:** новый язык контрактов, расширение поддерживаемого TS приложения, полная верификация frontend, другие сборщики, CLI-компилятор приложения, npm publish, доказательства корректности сторонних compiler plugins и минификатора.

## Decisions

1. Выделить отчёт и `verify`/`verifyPrepared` в модуль общего ядра. CLI сохраняет существующие exports и поведение. `prepareSource` дополнительно возвращает input, прочитанные файлы, символы контрактов, распознанные statement-узлы и разрешённые рёбра модулей. CompilerHost кеширует прочитанный текст, чтобы снимок не перечитывался между этапами.
2. Vite factory `valueProof({ entries: string[], limits? })`, `apply: build`, `enforce: pre`. Явная область позволяет обычному приложению импортировать проверенную библиотеку, не требуя поддержки UI/DOM в анализаторе. Dev server не изменяется. Каждый buildStart сбрасывает состояние, готовит графы и последовательно проверяет их; параллельные обращения к общему Z3-контексту сериализуются в ядре.
3. Удаление по AST-диапазонам через MagicString с high-resolution source maps. Полные statement-вызовы удаляются; named import/export списки фильтруются по символам API. `export *` прямо из API удаляется; остальные barrels остаются и очищаются в собственных модулях. Пустой import из обычного модуля сохраняется как side-effect import, чтобы не терять модульный граф. Type-only bindings можно сохранить для последующего TS emit. Не использовать regex или PURE-аннотации.
4. Плагин обрабатывает исходный текст только при точном совпадении с проверенным SourceFile. Разрешение рёбер из проверенного графа фиксируется по результату TS, предотвращая подмену через alias. Watch регистрирует входы подготовки, включая type-only файлы и исключённые контрактные модули. Перед выдачей bundle перечитываются входы для проверки неизменности. Query-варианты проверенных модулей отклоняются; повторные сборки не используют старый успех. Другие плагины после удаления остаются доверенной частью toolchain и не должны менять смысл проверенных функций.
5. Доверенный API определяется по canonical path исходного `src/contract.ts` либо `dist/src/contract.d.ts` рядом с установленным ядром. Bare import разрешается только для `ts-value-proof`, если он ведёт к этому API. Остальные ограничения анализа сохраняются. Пакет собирается TypeScript в `dist` с declarations и rewriteRelativeImportExtensions; exports ведут в JS, CLI имеет bin launcher. Пакет остаётся private; локальный tarball проверяется без публикации.
6. Vite — optional peer `^8.3.8` и точная dev dependency; TypeScript/Z3/MagicString — runtime зависимости инструмента. Публичный runtime export контракта не импортирует tooling. Build пакета — техническая сборка инструмента, не команда компиляции пользовательского приложения.

## Risks / Trade-offs

- Ограниченный язык → документировать отдельные entry points и условность гарантий для внешних callers.
- Изменения в watch и параллельные hooks → заново готовить снимок, сериализовать solver, проверять актуальность входов перед выпуском даже при кешированных модулях.
- Source maps могут содержать исходные контракты в sourcesContent → явно отличать от исполняемого JS; публикация source maps определяется конфигурацией приложения.
- Иные плагины способны менять код после проверки → описать доверенную границу toolchain; подмену до удаления отвергать.
- Ошибка сборки не удаляет прежний dist приложения → документировать отсутствие нового результата, не представлять старые файлы как новую успешную сборку.

## Migration Plan

Существующие относительные API imports и npm run verify работают как прежде. Новый пакет собирается `npm run build:package`, затем `npm pack` и устанавливается локально. Пользователь добавляет плагин в vite.config и выбирает entries. Для отката достаточно убрать плагин; контракты остаются обычными вызовами без runtime-проверок.
