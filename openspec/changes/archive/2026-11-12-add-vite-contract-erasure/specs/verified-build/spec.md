## Purpose

Определить проверку контрактов и их удаление при сборке приложения из того же снимка исходников, сохранив отдельную проверку через CLI.

## ADDED Requirements

### Requirement: Общее ядро проверки
CLI и интеграция сборки SHALL использовать общие правила подготовки, доказательства и отчёта. CLI SHALL сохранять JSON, коды завершения и отсутствие генерации JS.

#### Scenario: Совпадение отчётов
- **WHEN** API и CLI проверяют один граф с одинаковыми лимитами
- **THEN** статусы, обязательства и диагностика совпадают; CLI не создаёт JS

### Requirement: Явная область production-проверки
Vite-плагин SHALL принимать непустой список TS entry points относительно root проекта и необязательные лимиты solver. Production-сборка SHALL продолжаться только при verified для всех графов. Dev server SHALL оставаться без проверки и удаления. Код вне выбранных графов SHALL NOT объявляться доказанным.

#### Scenario: Недоказанный контракт
- **WHEN** любой граф имеет refuted, inconsistent, unknown, ошибку типов или неподдерживаемый синтаксис
- **THEN** сборка завершается ошибкой с причиной и не выпускает новый bundle

#### Scenario: Приложение за пределами проверяемого языка
- **WHEN** обычное приложение импортирует проверяемую библиотеку с указанным entry
- **THEN** библиотека проверяется и очищается, а остальной код собирается обычным образом

### Requirement: Сборка проверенного снимка
Проверка и удаление SHALL использовать один снимок. Изменение его входных файлов во время сборки или подмена исходника до обработки SHALL останавливать сборку. Относительные зависимости проверенных модулей SHALL разрешаться в те же реализации, что при проверке. Неподдерживаемые варианты загрузки этих модулей SHALL отклоняться.

#### Scenario: Изменение во время проверки
- **WHEN** реализация или type-only зависимость меняется после чтения снимка
- **THEN** сборка завершается ошибкой устаревшего снимка до выпуска результата

#### Scenario: Подмена другим плагином
- **WHEN** до удаления контрактов другой плагин изменяет исходник проверяемого модуля
- **THEN** сборка сообщает несовпадение исходника вместо применения старого доказательства

### Requirement: Удаление только распознанных контрактов
Сборка SHALL удалять распознанные объявления контрактов, их предикаты, bindings и re-exports доверенного API, исключая реализацию API из bundle. Она SHALL сохранять рабочие функции и остальные импорты/экспорты. Исходные файлы SHALL NOT изменяться. Использование результата contract SHALL оставаться неподдерживаемым.

#### Scenario: Смешанный barrel
- **WHEN** модуль переэкспортирует функцию и API под aliases, а потребитель объявляет контракт
- **THEN** рабочая функция сохраняется, API и контракт отсутствуют даже без tree shaking

#### Scenario: API вне проверяемой области
- **WHEN** production-сборка пытается загрузить доверенный API из непроверенного модуля
- **THEN** плагин завершает сборку с указанием необходимости включить модуль в область проверки

#### Scenario: External не обходит обработку
- **WHEN** API контрактов или зависимость собираемого проверенного модуля помечена external
- **THEN** сборка завершается ошибкой вместо переноса необработанного импорта в bundle

### Requirement: Source maps и повторные сборки
Преобразование SHALL предоставлять source maps к исходному TS. Каждая build-watch итерация SHALL заново проверять текущие входы, включая type-only зависимости и файлы контрактов, даже если они исчезли из runtime-графа после удаления. Старый успех SHALL NOT разрешать новую ошибочную сборку.

#### Scenario: Ошибка и исправление в watch
- **WHEN** после успешной сборки контракт становится ложным, а затем исправляется
- **THEN** следующая сборка отказывает, последующая проверяет исправленный снимок и проходит

### Requirement: Установка инструмента в другой проект
Локально собранный пакет SHALL предоставлять JS и declarations для `ts-value-proof`, `ts-value-proof/verify`, `ts-value-proof/vite` и CLI `ts-value-proof verify`. Runtime API SHALL NOT загружать solver или Vite. CLI SHALL работать без установленного Vite. Инструмент SHALL NOT требовать исполнения TS из node_modules.

#### Scenario: Локальный tarball
- **WHEN** пакет собирается, упаковывается и устанавливается в отдельный проект
- **THEN** контракт типизируется, CLI проверяет файл, а Vite-плагин собирает JS без контрактного API
