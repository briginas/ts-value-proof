# Design

## Context

См. proposal.md. Адаптер связывает параметры через TypeScript symbols, затем переводит statements в выражение результата. IR содержит только параметры и выражения; общий solver traversal проверяет область определения bigint-деления с учётом пути.

## Goals / Non-Goals

**Goals:** сохранить лексическую привязку и вычисление инициализаторов до позднейших условий, не добавляя изменяемое состояние в backend.

**Non-Goals:** SSA для присваиваний, function-valued locals, вызовы в инициализаторах и межветочная инициализация switch.

## Decisions

- Последовательно разбирать список statements с отдельной Map символов для каждого блока/ветви switch. После разбора инициализатора добавлять его выражение в Map. Вложенный блок копирует Map, поэтому затенение не меняет внешнюю привязку. Для if используются отдельные Map каждой ветви. Аннотации проверяет TypeScript; тип самого значения сохраняется в выражении.
- Подставлять чистые локальные выражения при чтении идентификатора. Вызовы и getters в инициализаторах запрещены, поэтому повторное символическое использование не создаёт эффектов или новых абстрактных результатов вызовов.
- Сохранить инициализаторы также в новом IR-узле `sequence { first, then }`, который вычисляет `first` и возвращает `then`. SourceStatement получает `evaluate`; lowering ставит sequence перед продолжением. Одна подстановка без этого узла ошибочно переносит потенциальное деление на ноль под поздний guard.
- `sequence` допустим только в теле; first не содержит вызовов, ветвлений или result. IR validation, inventory, dependency analysis, pretty printer и runtime traversal обходят обе части. Backend вычисляет first на текущем пути до then.
- В callPaths последовательность включается в условие пути как `path && sequence(first, true)`. Это сохраняет определённость инициализатора до позднего guard, а исходные call ID и аргументы остаются стабильны.
- Инициализаторы входят в зависимости проверяемого тела и последующих вызовов, даже если значение не используется. Независимые requires/ensures без result продолжают обходиться без тела. Это консервативная область проверки, явно описанная в документации.

## Risks / Trade-offs

- Подстановка может увеличить размер IR → использовать совместно одни объекты выражений; покрыть цепочки и повторное использование тестами. Компактные bindings можно добавить отдельно при необходимости.
- Пропущенный обход нового узла может потерять вызов или проверку → покрыть IR corruption, call coverage, runtime instrumentation и полный test suite.
- Switch имеет общую lexical scope в JavaScript → ссылки между clauses явно отклонять; локальные значения внутри собственной clause и вложенных блоков поддерживать.
- Инициализатор до guard способен выбросить исключение → сравнить результат проверки с исполнением исходного JavaScript; добавить отрицательные тесты для реализации и call obligations.

## Migration Plan

Обновить адаптер, общие IR consumers, тесты, README и обе usage-инструкции. Выполнить typecheck, npm test и package checks, синхронизировать спецификации и архивировать change. Откат возможен обычным revert коммита; формат contract API не меняется.
