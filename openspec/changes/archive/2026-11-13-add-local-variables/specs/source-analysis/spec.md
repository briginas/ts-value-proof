## MODIFIED Requirements

### Requirement: Поддерживаемые выражения и управление потоком

Анализатор SHALL поддерживать return, if/else, вложенные блоки, ранние возвраты и продолжения ветвей; +, -, *, /, унарный минус, сравнения, строгое равенство, boolean-литералы и &&, ||, !. Условия SHALL иметь тип boolean. Непрозрачные параметры и null-литералы SHALL допускаться в передаче и возврате вне зависимостей условия. Неподдерживаемая операция в зависимости SHALL давать unknown/unsupported-dependency. Мутации, циклы, try/catch, исходный ?: и числовая truthiness SHALL оставаться структурно неподдерживаемыми.

#### Scenario: Вложенная неполная ветка

- **WHEN** тело содержит if (x > 0n) { if (x > 1n) return 2n; } return 0n
- **THEN** представление тела сохраняет возврат 2n для x > 1n и продолжение с 0n для остальных путей

#### Scenario: Неподдерживаемая операция

- **WHEN** тело использует остаток, возведение в степень, исходный тернарный оператор или неявную проверку истинности bigint
- **THEN** остаток или возведение в степень в зависимости дают unknown/unsupported-dependency; неподдерживаемая структура тернарного оператора или числовая truthiness отклоняется

#### Scenario: Number без расширения операторов

- **WHEN** number-функция использует %, **, bitwise, нестрогое равенство, Math API или числовое условие if
- **THEN** неподдерживаемая операция в зависимости получает unknown/unsupported-dependency; структурно неподдерживаемые вызовы Math API и числовое условие if отклоняются как unsupported-code после проверки типов

#### Scenario: Числовое умножение

- **WHEN** bigint- или number-выражение использует `*` в return, requires, ensures, условии ветви или аргументе внутреннего вызова
- **THEN** анализатор сохраняет типы, приоритет и вложенность операции без неявного преобразования операндов

#### Scenario: Числовое деление

- **WHEN** bigint- или number-выражение использует `/` в return, requires, ensures, условии if/switch или аргументе внутреннего вызова
- **THEN** анализатор сохраняет типы, приоритет и левую ассоциативность без неявного преобразования операндов

## ADDED Requirements

### Requirement: Локальные объявления значений

Анализатор SHALL поддерживать локальные `const` и `let` с простым именем и обязательным инициализатором, с аннотацией типа или без неё. Несколько объявлений SHALL обрабатываться слева направо. Инициализаторы SHALL использовать прежнее подмножество выражений без вызовов и getters; `.length` примитивной строки допускается. Присваивания, инкременты, `var`, destructuring, `using` и объявления без значения SHALL отклоняться как unsupported-code после проверки типов.

#### Scenario: Цепочка локальных значений
- **WHEN** функция объявляет `const a = x + 1n, b: bigint = a * 2n; let c = b - a; return c;`
- **THEN** проверяется результат `x + 1n` с сохранением точности bigint

#### Scenario: Числа, строки и boolean
- **WHEN** локальные значения содержат number, строку, её длину или boolean-условие
- **THEN** их использование сохраняет binary64, UTF-16 и прежние ограничения непрозрачных параметров

#### Scenario: Неподдерживаемый инициализатор или изменение
- **WHEN** объявление использует вызов/getter, destructuring, `var`, отсутствующий инициализатор либо далее выполняется присваивание или инкремент
- **THEN** анализ отклоняет структуру, включая неиспользуемые объявления

### Requirement: Области видимости локальных переменных

Локальные переменные SHALL связываться по символам TypeScript с соблюдением вложенных блоков, порядка объявлений и затенения параметров, внешних переменных и глобальных NaN/Infinity. Объявления в одной switch-ветви SHALL быть доступны лишь внутри этой ветви и её вложенных блоков; ссылки из других ветвей SHALL отклоняться. Ошибки типов и доступа до инициализации, выявленные TypeScript, SHALL сохранять type-error.

#### Scenario: Затенение и выход из блока
- **WHEN** вложенный блок объявляет одноимённую переменную и затем выполнение продолжается за пределами блока
- **THEN** внутри блока используется локальное значение, а после блока — исходное внешнее значение

#### Scenario: Switch с локальными значениями
- **WHEN** switch-ветви объявляют локальные значения, используют break, return или fallthrough без ссылок между ветвями
- **THEN** значения и продолжения соответствуют JavaScript, а локальное значение не подменяет внешнюю переменную

#### Scenario: Недоступная переменная
- **WHEN** значение читается до инициализации, после выхода из области видимости или из другой switch-ветви
- **THEN** анализ отклоняется с type-error либо unsupported-code без доказательства

### Requirement: Сохранение вычисления локальных инициализаторов

При проверке результата и последующих вызовов анализатор SHALL сохранять вычисление предшествующих локальных инициализаторов на исходных путях, включая неиспользуемые значения. Поздняя проверка SHALL NOT оправдывать более раннее деление на ноль. Неподдерживаемый инициализатор в этой области SHALL давать unknown/unsupported-dependency с исходной позицией. Независимые предикаты, не использующие тело функции, SHALL сохранять выборочную проверку.

#### Scenario: Деление до проверки
- **WHEN** функция вычисляет `const q = x / y;` перед `if (y === 0n) return 0n; return q;`
- **THEN** проверка результата получает unknown/unsupported-dependency, если requires не исключает нулевой делитель

#### Scenario: Защищённый инициализатор
- **WHEN** ранний return исключает нулевой делитель до объявления `const q = x / y;`
- **THEN** инициализатор проверяется только на оставшихся путях

#### Scenario: Вызов после инициализатора
- **WHEN** вызов с предусловием следует за локальным инициализатором и условной ветвью
- **THEN** сохраняются исходные аргументы, call ID и пути, а вычисление инициализатора проверяется до использования условия пути

#### Scenario: Независимый контракт
- **WHEN** requires или ensures зависит только от входов, а неподдерживаемое локальное вычисление не связано с проверяемым вызовом
- **THEN** независимый предикат остаётся проверяемым без обещания корректности всего тела
