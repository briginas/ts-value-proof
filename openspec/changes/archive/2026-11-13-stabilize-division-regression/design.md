# Design

## Context

См. proposal.md. Тест последовательно проверяет bigint и number, затем повторно вызывает верификацию через генератор регрессий. В number-fixture вход не ограничен, а Z3 имеет таймаут 5000 мс.

## Goals / Non-Goals

**Goals:** сохранить интеграционную проверку verify → manifest → replay с простым допустимым контрпримером и полезной диагностикой CI.

**Non-Goals:** ускорение solver, увеличение его таймаутов, изменение статусов или формата manifest.

## Decisions

- Добавить `requires: x => x === 0` к number-fixture. Оба знака нуля дают `NaN` при делении на себя; точная кодировка сохраняется существующим генератором. Свободный поиск по binary64 не нужен для проверки сохранения и replay.
- Передать имя fixture и JSON отчёта вторым аргументом `expect`, чтобы будущие `unknown` раскрывали reasonCode и reason.
- Сохранить строгие ожидания `refuted`, один сохранённый случай и `failed` при replay; не разрешать `unknown` как успешный результат теста.
- Увеличение таймаута отклонено: оно оставляет зависимость от скорости runner и замедляет диагностику.

## Risks / Trade-offs

- Сужение входа уменьшает поиск особых значений в этом тесте → существующие тесты binary64 и resource limits продолжают проверять арифметику и `unknown`; bigint-часть остаётся прежней.
- Локальный успех не гарантирует результат на Linux → после локальных проверок отправить коммит и дождаться обеих GitHub jobs.
