# Design

## Context

Адаптер строит SourceStatement, затем returnExpression превращает if в Expr.ternary, распространяя продолжения с конца блока. Backend, анализ зависимостей и проверка целостности уже поддерживают ternary и строгое равенство. Мотивация описана в proposal.md.

## Goals / Non-Goals

**Goals:** выразить switch существующими Expr, сохранив выбор, fallthrough, вложенные выходы и идентичность вызовов.

**Non-Goals:** локальные переменные, мутации, циклы, labeled break, вызовы в выборе/метках, новые модели типов и новый backend IR.

## Decisions

1. Добавить switch с ordered clauses и break в SourceStatement. Разбирать каждое исходное тело ровно один раз до lowering, чтобы не дублировать регистрацию call ID. Альтернатива — перевод непосредственно AST в повторные if — смешивает выбор и выполнение и усложняет учет вызовов.
2. Дополнить returnExpression отдельным контекстом break с продолжением ближайшего switch. Объект контекста различает отсутствие цели break и цель без возвращаемого значения. Обычные блоки/if передают контекст без изменений, вложенный switch заменяет его своим продолжением.
3. Обходить тела clauses с конца, передавая следующую clause как normal continuation, а код после switch как break continuation. Затем построить цепочку ternary по case в исходном порядке с fallback в тело default (где бы он ни стоял) или продолжение. Неполный путь возвращает undefined, как и существующий if lowering; он не подменяется фиктивным значением. Пустой switch равен своему продолжению.
4. Дублирование выражения выбора в формулах допустимо только для выражений без побочных эффектов. Перед разбором выбора и меток отклонять calls, mutation и property/element access кроме length примитивной строки; существующий expression parser отклоняет остальные неподдерживаемые структуры. Разрешенные, но не моделируемые операции продолжают создавать unsupported-зависимости. Boolean-параметры и unions не получают новой семантики.
5. Сохранить существующий coverage/inventory контроль: исходные вызовы в скопированных ветвях имеют прежние ID; удаленные недостижимые вызовы приводят к отказу, а не к ослаблению контроля. Строгое равенство использует уже существующие backend операции, включая binary64 и UTF-16.
6. Проверить реальные исходники против полученного IR на сетке входов и случайных входах с фиксированным seed; отдельно проверить solver, unknown, контрпримеры, runtime, call paths и CLI. Использовать существующие test utilities и Vitest.

## Risks / Trade-offs

- Неверный default/fallthrough или перехват break внешним switch → дифференциальные тесты с default в начале/середине/конце и условными вложенными выходами.
- Повторное вычисление эффекта → структурная проверка выбора/меток, включая пустые switch; вызовы остаются разрешены только в return.
- Рост дерева при общих продолжениях → переиспользование Expr в памяти; сериализация и перечисление путей сохраняют существующую стоимость развернутых ветвей.
- Проверки не являются формальным доказательством → сочетание shape, differential и интеграционных проверок, без заявления о доказанности самого адаптера.

## Migration Plan

Изменение аддитивное, формат публичного IR прежний. Обновить документацию поддерживаемого языка, выполнить typecheck и полный test suite, синхронизировать specs и архивировать change. Откат — отмена коммита.
