# Design

## Context

Адаптер помечает `*` как unsupported. IR и общий NumericModel поддерживают только сложение и вычитание. Bigint backend использует Z3 Int, number backend — FP64 с RNE; runtime исполняет исходный TypeScript.

## Goals / Non-Goals

**Goals:** добавить одну операцию через существующий путь анализа и обязательств, сохранив типы, диагностику и точные контрпримеры.

**Non-Goals:** деление, остаток, степень, расширение неявных преобразований и оптимизация нелинейного solver.

## Decisions

- Добавить `*` в binary IR и адаптер, а `mul` — в NumericModel. Валидатор применяет прежние ограничения числовых операндов; строки не получают умножение.
- Bigint использует целочисленный `mul`, без ограничения разрядности. Замена на real или fixed-width нарушила бы текущую модель.
- Number использует `mk_fpa_mul` с RNE. Не переносить integer shortcut сложения на умножение: прямой FP сохраняет signed zero, NaN, округление и overflow без новых доказательных предпосылок.
- Обход зависимостей, печать выражений, runtime и генераторы уже работают с binary-узлами или исходным TS; отдельный интерпретатор не нужен.
- Проверять результаты против native JS: bigint за пределами safe integer, number-корпус со специальными значениями и ties-to-even. Добавить проверки исходников, предикатов, вызовов, воспроизведения и resource limits. Старые проверки unsupported умножения заменить делением.

## Risks / Trade-offs

- Нелинейные Int и FP формулы могут быть дорогими → сохранить timeout/resourceLimit и unknown; избегать обещаний полной разрешимости.
- FP тождества неверны на NaN/Infinity → отдельные положительные и отрицательные проверки, Object.is для signed zero.
- Пропуск уровня адаптера/IR → source-to-solver проверки и отрицательные проверки типов.

## Migration Plan

Обновить поддержку и документацию вместе; миграция данных не нужна. Откат выполняется отменой change-коммита.
