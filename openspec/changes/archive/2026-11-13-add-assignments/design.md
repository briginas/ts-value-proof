# Design

## Context

См. proposal.md. Адаптер немедленно подставляет локальные значения; returnExpression разворачивает продолжения с конца. Немедленная подстановка не сохраняет изменения внешних переменных в блоках и ветвях. IR уже имеет sequence для вычисления неиспользованных инициализаторов.

## Goals / Non-Goals

**Goals:** сохранить существующий expression IR и backend, порядок вычислений, лексические привязки и исходные аргументы контрактов.

**Non-Goals:** изменяемая память/объекты, циклы, новые числовые операции и расширение мест вызовов.

## Decisions

- Парсить локальные объявления и присваивания в промежуточный statement bind. Каждому локальному символу дать уникальное внутреннее имя, невозможное в TypeScript identifier. Параметры в теле обозначают текущие значения; предикаты строятся независимо относительно исходных параметров.
- При обратном разворачивании bind подставлять RHS вместо его имени во всём продолжении, включая условия, sequence, зависимости unsupported и аргументы вызовов. RHS не подставляется сам в себя. Сохранять sequence(RHS, continuation), чтобы преждевременное деление на ноль или неподдерживаемое вычисление не исчезало после перезаписи.
- Использовать существующие продолжения if и switch: присваивания меняют только достигнутый путь; break получает продолжение ближайшего switch. Выбор switch находится вне тел ветвей и сохраняет значения до их исполнения. Отдельные карты символов блоков и case сохраняют прежние ограничения видимости.
- Составные присваивания свести к существующим бинарным операциям с прежним значением слева. Не вводить coercion: смешанная строковая операция получает unsupported-dependency как обычный +.
- Копии call ID проверять на одинаковую исходную позицию, владельца, callee и arity; аргументы могут различаться после подстановок по путям. Проверять типы каждой копии и сохранять source inventory для обнаружения последующего повреждения аргументов. Runtime продолжает исполнять исходный TypeScript и регистрировать фактические аргументы.
- Альтернатива — forward SSA с объединением окружений — потребовала бы новых промежуточных значений в условиях/аргументах и изменений backend. Обратная подстановка использует уже существующие ветви и выражения.

## Risks / Trade-offs

- Разворачивание ветвей и подстановок увеличивает IR → сохранить существующее ограниченное подмножество без циклов и проверить реальные небольшие ветвления.
- Ошибка снимков при alias/shadowing или break → отдельные shape, solver и native runtime проверки, включая общий call site с разными аргументами.
- Ослабление проверки одинаковых аргументов call ID → сохранить проверки источника/цели/типов и inventory; добавить отрицательные тесты повреждения.
- Успешные тесты не являются формальным доказательством корректности трансляции.
