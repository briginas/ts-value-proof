# runtime-execution Specification


## Purpose

Исполнять проверенный граф TypeScript-модулей и исходные предикаты контрактов для тестирования, сохраняя привязку функций и мест вызова к исходному коду.

## Requirements

### Requirement: Проверка исходников до исполнения
Тестовый runtime SHALL проверять типы, поддерживаемый синтаксис, граф модулей и IR перед исполнением исходников и SHALL NOT исполнять отклонённую программу. Тестовый режим SHALL быть предназначен для доверенного кода проекта, без гарантий security sandbox.

#### Scenario: Неподдерживаемая инструкция отклоняется до исполнения
- **WHEN** входной модуль содержит неподдерживаемый top-level `throw`
- **THEN** создание runtime завершается ошибкой проверки исходников до исполнения этой инструкции.

#### Scenario: Импорт вне проверенного графа
- **WHEN** тестовый загрузчик пытается загрузить модуль, отсутствующий в проверенном снимке исходников
- **THEN** загрузка завершается ошибкой и этот модуль не исполняется.

#### Scenario: Статически допустимый непрозрачный аргумент

- **WHEN** граф прошёл выборочную статическую проверку, но имеет непрозрачные параметры, результат или непригодное для числового runtime тело
- **THEN** runtime отказывает до исполнения с причиной неподдерживаемой runtime-области; статический результат не переписывается

### Requirement: Исполнение настоящих функций и предикатов
Runtime SHALL исполнять реальные тела функций и `requires`/`ensures` из проверенного снимка, компилируя тестовую копию в памяти. Он SHALL NOT вычислять результат интерпретацией IR, изменять исходные файлы или заменять поведение пользовательского `contract()`.

#### Scenario: Точная арифметика при исполнении
- **WHEN** поддерживаемая функция вызывается с bigint за пределами точности `number`
- **THEN** результат вычисляется JavaScript bigint без потери точности, а `ensures` получает этот результат и исходные аргументы.

#### Scenario: Реальное округление number

- **WHEN** поддерживаемая функция возвращает 0.1 + 0.2
- **THEN** ensures получает реальный результат JavaScript 0.30000000000000004, а не 0.3

### Requirement: Сохранение идентичности функций и контрактов
Runtime SHALL сохранять идентичность исходных функций через private-объявления, aliases, imports, re-exports и отдельные модули контрактов. Он SHALL проверять полноту регистрации функций и контрактов и SHALL отклонять отсутствующую или несовпадающую привязку.

#### Scenario: Одноимённые функции разных модулей
- **WHEN** caller использует две одноимённые функции через импорт и re-export, а контракт одной объявлен в отдельном модуле
- **THEN** выполняются соответствующие исходные функции с собственными контрактами без смешения символов.

#### Scenario: Конфликт с именем инструментации
- **WHEN** исходный код содержит идентификатор `__vc_runtime`
- **THEN** инструментация выбирает свободное имя и сохраняет исходное поведение.

#### Scenario: Экспорт с именем __proto__
- **WHEN** поддерживаемый модуль экспортирует функцию `__proto__` с контрактом
- **THEN** импортированный вызов сохраняет исходную функцию и её контракт.

### Requirement: Проверка аргументов и результата исполнения
Runtime SHALL принимать только существующую функцию, правильное число аргументов поддерживаемого типа сигнатуры и вход, удовлетворяющий её `requires`, если оно задано. Для функции без контракта `accepts` SHALL возвращать true, а `execute` SHALL возвращать результат без значения `ensures`. Результат исполнения SHALL иметь поддерживаемый тип результата сигнатуры. NaN, бесконечности и оба нуля SHALL допускаться для number, если requires не запрещает их.

#### Scenario: Недопустимый вход функции с контрактом
- **WHEN** переданные аргументы нарушают собственное `requires` функции
- **THEN** `accepts` возвращает false, а `execute` отклоняет выполнение.

#### Scenario: Неверная привязка или форма аргументов
- **WHEN** имя функции неизвестно, число аргументов неверно или аргумент имеет тип, отличный от типа параметра
- **THEN** runtime сообщает ошибку вместо выполнения функции с такой привязкой.

#### Scenario: Caller без контракта
- **WHEN** выполняется поддерживаемая функция без собственного контракта
- **THEN** runtime возвращает её bigint-, number- или string-результат согласно сигнатуре и наблюдённые внутренние вызовы, а `ensures` отсутствует.

#### Scenario: Отсутствие скрытого фильтра конечности

- **WHEN** number identity получает NaN, Infinity, -Infinity или -0 при requires: () => true
- **THEN** runtime исполняет функцию и сохраняет точное значение аргумента и результата

#### Scenario: Неверная числовая модель входа

- **WHEN** в number-функцию передан bigint либо в bigint-функцию number
- **THEN** runtime отклоняет вход без преобразования типа

#### Scenario: Ensures-only runtime

- **WHEN** поддерживаемая числовая функция имеет только ensures
- **THEN** accepts возвращает true для корректных по арности и типам входов; execute проверяет реальный результат через ensures

#### Scenario: Requires-only runtime

- **WHEN** поддерживаемая числовая функция имеет только requires
- **THEN** accepts и execute проверяют requires; результат execute не содержит значения ensures

### Requirement: Наблюдение фактических внутренних вызовов
Runtime SHALL записывать идентичность каждого исполненного места вызова, фактические аргументы поддерживаемых типов callee и результат `requires` callee, если оно задано, до выполнения исходного callee. Нарушенное предусловие SHALL сохраняться в наблюдениях. Копии одного места вызова в IR SHALL иметь общий source ID и одну позицию в упорядоченном списке мест вызова.

#### Scenario: Нарушение при истинном постусловии caller
- **WHEN** caller имеет `ensures: () => true`, но передаёт callee аргументы, нарушающие его `requires`
- **THEN** наблюдение содержит фактические аргументы и `accepted: false`, даже если `ensures` caller истинно.

#### Scenario: Общее продолжение нескольких ветвей
- **WHEN** адаптер копирует одно исходное место вызова в несколько ветвей IR
- **THEN** список мест вызова учитывает его один раз по source ID, а execution содержит только фактически исполненные вызовы.

#### Scenario: NaN в аргументе callee

- **WHEN** number-caller вызывает callee с NaN, а requires callee задаёт x >= 0
- **THEN** наблюдение сохраняет NaN и accepted: false до исполнения callee

#### Scenario: Callee без requires

- **WHEN** исполняется вызов callee с ensures-only контрактом
- **THEN** наблюдение сохраняет идентичность и аргументы; accepted равен true без вызова отсутствующего предиката

### Requirement: Отклонение конфликтов CommonJS
Runtime SHALL отклонять top-level bindings `require`, `exports`, `module`, `Object`, `__createBinding`, `__exportStar` и `__esModule`, конфликтующие с тестовой компиляцией в CommonJS. Это ограничение SHALL применяться к тестовому режиму отдельно от статической верификации.

#### Scenario: Зарезервированное имя функции
- **WHEN** поддерживаемый исходный модуль объявляет top-level функцию `Object` или `__exportStar`
- **THEN** создание runtime завершается ошибкой о CommonJS-reserved binding.

### Requirement: Строковые и смешанные runtime-сигнатуры

Runtime SHALL исполнять поддерживаемый граф string/number, проверяя тип каждого параметра и результата по сигнатуре без преобразования. .length SHALL допускаться для примитивной строки, включая аргументы внутренних вызовов. Непрозрачные типы и графы bigint со string/number SHALL оставаться неподдерживаемыми в runtime.

#### Scenario: Смешанная сигнатура
- **WHEN** функция (s: string, n: number): string получает "😀" и 2
- **THEN** runtime исполняет настоящую функцию и предикаты; неверный тип любой позиции отклоняется

#### Scenario: Числовой результат длины
- **WHEN** функция (s: string): number возвращает s.length для одиночного суррогата
- **THEN** результат равен 1 и имеет тип number
