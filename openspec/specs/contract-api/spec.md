# contract-api Specification


## Purpose

Описывать предусловия и постусловия функции с выводом типов из её сигнатуры, сохраняя исходную функцию для статической проверки и тестирования.

## Requirements

### Requirement: Контракт сохраняет функцию и спецификацию

API SHALL предоставлять `contract(fn, specification)` с requires, ensures или обоими предикатами и возвращать исходные ссылки в readonly-полях fn и specification. Пустой контракт и контракт без хотя бы одного определённого предиката SHALL отклоняться типизацией. Создание контракта SHALL NOT исполнять функцию или предикаты, добавлять отсутствующий предикат, оборачивать функцию или запускать верификацию.

#### Scenario: Создание контракта не исполняет код
- **WHEN** контракт создаётся для функции и предикатов со счётчиками вызовов
- **THEN** все счётчики остаются нулевыми, а возвращённые ссылки совпадают с переданными

#### Scenario: Независимые предикаты

- **WHEN** переданы requires-only, ensures-only и полный контракт
- **THEN** все три формы типизируются; отсутствующий предикат не появляется в specification

#### Scenario: Пустой контракт

- **WHEN** передан {} либо оба предиката равны undefined
- **THEN** TypeScript сообщает ошибку

### Requirement: Типы предикатов выводятся из функции
`Specification<F>` SHALL принимать аргументы F в `requires` и результат F перед исходными аргументами в `ensures`. Каждый указанный предикат SHALL возвращать boolean. Предикаты SHALL NOT менять тип F при выводе типов. `BoundContract<F>` SHALL сохранять сигнатуру F.

#### Scenario: Вывод типов аргументов и результата
- **WHEN** контракт связывается с функцией `(balance: bigint, amount: bigint) => bigint`
- **THEN** параметры requires и результат с параметрами ensures имеют тип bigint, а bound.fn сохраняет исходную арность

#### Scenario: Несовместимые предикаты
- **WHEN** предикат требует string вместо bigint, лишний обязательный аргумент или возвращает не boolean
- **THEN** проверка TypeScript сообщает ошибку

#### Scenario: API допускает более широкий набор типов
- **WHEN** контракт описывает функцию с number, string или объектами
- **THEN** типы аргументов и результата корректно выводятся без обещания поддержки этих типов статическим верификатором

#### Scenario: Позиционная выборочная проверка

- **WHEN** функция принимает label: string и amount: number, а requires задан как (_label, amount) => amount >= 0
- **THEN** параметры выводятся как string и number без перестановки; ensures не обязателен

### Requirement: Сохранённая спецификация сохраняет совместимость сигнатуры
Сохранённая `Specification<F>` SHALL быть инвариантной по F и отклоняться после несовместимого изменения аргументов или результата. Функции с одинаковой структурной сигнатурой SHALL оставаться совместимыми на уровне TypeScript.

#### Scenario: Изменение сигнатуры
- **WHEN** у функции меняется тип аргумента или результата, удаляется обязательный параметр, параметр становится optional либо результат допускает null
- **THEN** повторная привязка старой спецификации и несовместимое присваивание спецификации отклоняются TypeScript

#### Scenario: Функции одинаковой сигнатуры
- **WHEN** спецификация привязывается к другой функции с той же сигнатурой
- **THEN** TypeScript принимает привязку; идентичность конкретных объявлений не заявляется гарантией системы типов

#### Scenario: Инвариантность неполного контракта

- **WHEN** сохранённая requires-only или ensures-only спецификация повторно привязывается после несовместимого изменения F
- **THEN** TypeScript отклоняет привязку так же, как для полного контракта

### Requirement: Aliases и импорты сохраняют типизацию API
Типизация контракта SHALL сохранять аргументы, арность и результат через const aliases, named imports и re-exports.

#### Scenario: Импортированный alias
- **WHEN** функция и API импортируются через re-export и переименование
- **THEN** корректные предикаты принимаются, а несовместимые аргументы, результаты и вызовы bound.fn отклоняются
