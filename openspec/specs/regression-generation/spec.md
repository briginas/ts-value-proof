# regression-generation Specification


## Purpose

Преобразовывать подтверждённые исполнением статические контрпримеры в точные сохранённые случаи и запускаемый Vitest suite для повторной проверки после исправлений.

## Requirements

### Requirement: Подтверждение контрпримеров исполнением
Генератор SHALL рассматривать только статические результаты `disproved` для implementation и call. Он SHALL сохранять случай только после воспроизведения нарушения реальным исполнением на допустимых входах caller или проверяемой функции. Результаты `unknown` SHALL NOT сохраняться как подтверждённые регрессии.

#### Scenario: Нарушение реализации
- **WHEN** статический контрпример удовлетворяет `requires`, а реальный результат нарушает `ensures`
- **THEN** генератор сохраняет implementation-регрессию с этими входами.

#### Scenario: Нарушение конкретного места вызова
- **WHEN** статическая проверка сообщает нарушенный call
- **THEN** генератор сохраняет регрессию только если исполнение нарушает `requires` именно в указанном source call, включая caller без контракта.

#### Scenario: Другое место вызова нарушает контракт
- **WHEN** исполнение нарушает предусловие другого вызова, но не вызова из статического результата
- **THEN** исходный результат попадает в `unconfirmed`, а не в сохранённые случаи.

#### Scenario: Слабое постусловие callee
- **WHEN** статическая проверка возвращает `unknown` из-за слабого контракта callee
- **THEN** генератор не сохраняет абстрактную модель как регрессию и учитывает unknown в отчёте.

#### Scenario: Подтверждение number после JSON round-trip

- **WHEN** number-контрпример содержит NaN, -0, бесконечность или граничное конечное значение
- **THEN** после точной сериализации и декодирования генератор подтверждает нарушение настоящим requires/телом/ensures; неподтверждённая модель попадает в unconfirmed

#### Scenario: Неполный вход после выборочной проверки

- **WHEN** статическая проверка имеет unknown/incomplete-counterexample либо unsupported-dependency
- **THEN** генератор не сохраняет случай и не дополняет вход объектами или undefined

#### Scenario: Непригодный для runtime граф

- **WHEN** статический анализ принимает непрозрачную сигнатуру, но runtime не поддерживает весь граф
- **THEN** генерация завершается явной ошибкой с кодом 2 до исполнения; прежние результаты не объявляются текущим успехом

### Requirement: Точный manifest регрессий

Генератор SHALL создавать manifest с entry и массивом случаев: version 1 для bigint, version 2 для number и version 3 для string/number. Входы SHALL храниться в исходном порядке параметров без потери точности: bigint — десятичные строки с n, number — точная number-кодировка. Случай SHALL хранить вид обязательства, идентичность функции и исторические позиции. Call-случай SHALL также хранить позицию, ordinal, число мест вызова caller и идентичность callee.

#### Scenario: Большой отрицательный вход
- **WHEN** контрпример содержит отрицательный bigint вне диапазона точных целых `number`, включая параметр `__proto__`
- **THEN** manifest сохраняет полное значение без преобразования в `number` и в исходном порядке параметров.

#### Scenario: Идентичность функции
- **WHEN** записывается сохранённый случай
- **THEN** ключ функции содержит путь модуля относительно каталога entry, исходное имя и упорядоченные имена параметров, а entry хранится относительно каталога manifest.

#### Scenario: Повторяющийся подтверждённый случай
- **WHEN** результаты содержат полностью одинаковые сохранённые случаи
- **THEN** manifest содержит один экземпляр такого случая.

#### Scenario: Number manifest

- **WHEN** генератор сохраняет подтверждённую number-регрессию
- **THEN** manifest имеет version: 2 и semantics: number-ieee754-binary64; function и callee keys дополнены той же semantics, включая функции без параметров

#### Scenario: Совместимость bigint-записи

- **WHEN** генератор запускается для существующего bigint-примера
- **THEN** manifest остаётся version: 1 с прежними строками входов и формой ключей

#### Scenario: Независимые предикаты в числовом графе

- **WHEN** полный числовой контрпример call или implementation подтверждён при контракте с одним предикатом
- **THEN** сохраняется существующий manifest v1 или v2 без фиктивных предикатов и нового формата

### Requirement: Генерация файлов для текущих исходников
Генератор SHALL создавать `cases.json` и `contracts.test.ts` в выбранном каталоге и заменять оба файла при повторном запуске. Сгенерированные regression-тесты SHALL читать текущие исходники и проверять сохранённые входы. Они SHALL NOT включать копию исходной программы или исполняемые строки контрпримеров.

#### Scenario: Повторное исполнение после исправления
- **WHEN** после генерации исправлена реализация или guard без несовместимого изменения привязки
- **THEN** тот же сгенерированный regression-тест проверяет исправленные исходники без повторной генерации случаев.

#### Scenario: Повторная генерация
- **WHEN** генератор повторно запускается для существующего выходного каталога
- **THEN** `cases.json` и `contracts.test.ts` отражают текущий результат генерации.

#### Scenario: Нет подтверждённых случаев
- **WHEN** генератор не находит подтверждённых регрессий
- **THEN** manifest содержит пустой массив случаев, а regression-часть suite не создаёт тестов; дополнительные property-тесты определяются capability `property-testing`.

### Requirement: Отчёт и коды завершения генерации
CLI генерации SHALL выводить при успешной генерации JSON с путями файлов, количеством случаев, `unconfirmed` и `unknownObligations`. Он SHALL возвращать код 0 при отсутствии неподтверждённых результатов, включая ноль случаев, и код 2 при ошибке или наличии `unconfirmed`. Ошибка запуска SHALL выводиться в stderr. Код 0 SHALL NOT означать доказанность программы.

#### Scenario: Успешная генерация для ошибочной программы
- **WHEN** нарушение подтверждено, случай записан и `unconfirmed` пуст
- **THEN** CLI возвращает 0, хотя последующий regression-тест воспроизводит ошибку программы.

#### Scenario: Неподтверждённый статический результат
- **WHEN** хотя бы один статический `disproved` не подтверждён исполнением
- **THEN** JSON содержит его в `unconfirmed`, а CLI возвращает 2.

#### Scenario: Ошибка подготовки входного кода
- **WHEN** генерация завершается исключением при подготовке или обработке исходников
- **THEN** CLI выводит сообщение ошибки в stderr и возвращает 2.

### Requirement: Строковый manifest v3

Для графа с string в сигнатурах генератор SHALL создавать manifest version 3 с semantics string-utf16-number-binary64. Ключи function/callee SHALL включать упорядоченные типы параметров и тип результата. Входы SHALL кодироваться по типам. Случаи SHALL сохраняться только после подтверждения реальным исполнением после JSON round-trip. Форматы v1/v2 SHALL сохраняться для прежних графов.

#### Scenario: Сохранение строки
- **WHEN** строковое нарушение подтверждено на входе с одиночным суррогатом
- **THEN** manifest v3 сохраняет этот вход без потери кодовых единиц и содержит типы сигнатуры
