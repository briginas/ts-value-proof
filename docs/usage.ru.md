# Руководство по ts-value-proof

[Краткое описание](../README.md) · [English](usage.md)

Прототип статической проверки контрактов TypeScript через Z3. Проверяет
предусловия вызовов (`requires`) и постусловия функций (`ensures`), находит
контрпримеры и генерирует регрессионные и property-based тесты.
Поддерживает точную арифметику `bigint`, JavaScript `number` (IEEE-754 binary64)
и базовые операции со строками `string` (UTF-16).

## Контракты

```ts
import { contract } from "../src/contract.js";

export function withdraw(balance: bigint, amount: bigint): bigint {
  return balance - amount;
}

contract(withdraw, {
  requires: (balance, amount) => balance >= 0n && amount > 0n && amount <= balance,
  ensures: (result, balance, amount) => result >= 0n && result === balance - amount,
});
```

Пример рассчитан на файл в `examples/`. Типы предикатов выводятся из функции:
`requires` получает её аргументы, `ensures` — сначала результат, затем аргументы.
Можно задать один предикат или оба. Без `requires` входы не ограничены;
без `ensures` нет гарантии о результате. Сам `contract()` только сохраняет
описание и не выполняет проверки при вызове функции.

## Запуск

Нужен Node.js `^24.12.0 || >=26.0.0`. Все команды выполняются из корня репозитория.

```sh
npm ci --ignore-scripts --no-audit --no-fund --cache ./work/npm-cache
npm run verify -- examples/bigint-exact.ts    # verified, код 0
npm run verify -- examples/withdraw.ts        # refuted, код 1
npm run verify -- examples/number-identity.ts # verified, код 0
npm run verify -- examples/withdraw-number.ts # refuted, код 1
npm run verify -- examples/string-basics.ts   # verified, код 0
```

В `withdraw.ts` намеренно оставлен вызов без проверки достаточности баланса.
В `withdraw-number.ts` ошибки связаны с NaN и Infinity.
Другие примеры: [межфайловые контракты](../examples/modules/index.ts),
[только requires](../examples/selective-requires.ts),
[умножение](../examples/multiplication.ts),
[деление bigint](../examples/division.ts), [деление number](../examples/division-number.ts),
[выборочная проверка](../examples/selective-mixed.ts).

CLI выводит JSON и сохраняет тот же отчёт в `work/verification.json`.
Для чистого JSON в stdout используйте `npm run --silent verify -- <file>`.

| Итоговый `status` | Код | Значение |
| --- | --- | --- |
| `verified` | 0 | Все проверяемые условия доказаны. |
| `refuted` | 1 | Найдено нарушение постусловия или предусловия вызова. |
| `inconsistent` | 1 | Предусловия противоречивы. |
| `unknown` | 2 | Доказательство не получено, код не поддержан или произошла ошибка. |

Оценивайте итоговый статус всего отчёта. Поле `scope` описывает область проверки,
`results` — отдельные условия, их исходные позиции, причины и контрпримеры.
`verified` относится только к заданным контрактам и вызовам внутри проверенного
графа; соблюдение предусловий внешними callers не проверяется.

## Генерация тестов

```sh
npm run generate-tests -- examples/withdraw.ts work/generated
npx vitest run work/generated/contracts.test.ts --maxWorkers=1
```

Генератор записывает `cases.json` с подтверждёнными исполнением контрпримерами
и `contracts.test.ts` для их повторного запуска и property-based проверок
через fast-check. Повторная генерация заменяет оба файла.

Для `withdraw.ts` ожидается падение регрессии `payUnchecked`. После добавления
проверки `amount > balance` перед вызовом тест проходит без повторной генерации.
Сохраняйте `cases.json`, чтобы проверять исправления на прежних входах.
Каталог `work/` исключён из Git; для хранения тестов в репозитории выбирайте другой.
После изменения сигнатур или структуры вызовов сохранённые случаи могут стать
неприменимыми (`inapplicable`), что считается падением теста.

Код 0 генератора означает успешную запись файлов, даже если контрпримеров нет;
код 2 — ошибку или неподтверждённый контрпример. Это не результат верификации.
Успех property-based тестов также не является доказательством.
Тестовый режим исполняет исходный код и рассчитан на доверенный проект;
статический верификатор код не исполняет.

## Ограничения

- Перед анализом исходники проверяются TypeScript с фиксированными настройками
  `strict`, `noImplicitReturns`, ES2022 и NodeNext, независимо от пользовательского
  `tsconfig.json`. Ошибки типов прерывают анализ; директивы `@ts-ignore`,
  `@ts-nocheck` и `@ts-expect-error` не допускаются.
- Поддерживаются именованные синхронные функции с явными типами обязательных
  параметров и результата; `return`, `if/else`, блоки, `switch`; операции `+`, `-`, `*`, `/`,
  унарный минус, сравнения, `===`, `!==`, `&&`, `||`, `!`.
- В `switch` поддерживаются `case`, `default` в любой позиции, fallthrough,
  вложенные `switch` и `break` без метки, в том числе внутри `if`.
  Выбор использует строгое равенство: `NaN` не совпадает ни с одной меткой,
  а `+0` совпадает с `-0`. В выражении выбора и метках нельзя использовать
  вызовы, мутации и обращения к свойствам, кроме `.length` примитивной строки.
  Сохраняются ограничения типов и моделей; пути без возврата и `break` с меткой
  не поддерживаются.
- Локальные `const` и `let` поддерживают простые имена и обязательные начальные
  значения, с аннотацией типа или без неё, несколько объявлений подряд и затенение
  во вложенных блоках. Значения можно использовать в `return`, условиях и аргументах
  вызовов. В инициализаторах запрещены вызовы и доступ к свойствам, кроме `.length`
  примитивной строки. Переменную из одной ветви `switch` нельзя читать в другой.
  При проверке результата или последующего вызова учитываются предшествующие
  инициализаторы, даже если их значения не используются: поздняя проверка делителя
  не защищает более раннее деление. Независимые предикаты, не использующие тело,
  сохраняют выборочную проверку. См. [пример](../examples/local-variables.ts).
- Присваивания `=`, `+=`, `-=`, `*=`, `/=` поддерживаются отдельными statements
  для локальных `let` и параметров, в том числе в блоках, `if/else` и `switch`
  с fallthrough и `break`. Строковый `+=` соединяет строки без преобразования типов.
  Справа действуют те же ограничения, что в инициализаторах. Ранее сохранённые
  копии сохраняют свои значения; параметры контрактов обозначают исходные аргументы.
  Предшествующие присваивания учитываются даже после перезаписи: поздняя проверка
  не защищает более раннее деление на ноль. См. [пример](../examples/assignments.ts).
- Тернарные выражения (`условие ? да : нет`) поддерживают вложенность, `return`,
  операнды, локальные инициализаторы, значения присваиваний, условия `if`/`switch`,
  метки `case`, аргументы вызовов и предикаты контрактов. Условие должно иметь тип
  boolean, а обе ветви — один вид значения (`bigint`, `number`, `string`, boolean
  или непрозрачный). В выражениях допускаются union литералов одного примитивного вида.
  Выполняется только выбранная ветвь: `y === 0n ? 0n : x / y` защищает деление.
  В ветвях возвращаемого выражения разрешены вызовы с обычными ограничениями;
  вызовы в условии и мутации внутри выражения запрещены. Boolean-параметры остаются
  непрозрачными: зависимость от них даёт `unknown`.
  См. [пример](../examples/ternary-expressions.ts).
- Запись в свойства и элементы, присваивания внутри выражений, `++`/`--`, остальные
  составные присваивания, `var`, destructuring, объявления без начального значения, `using`, циклы, рекурсия, `async`, generics, overloads,
  optional/rest/default-параметры пока не поддерживаются.
  Остаток, возведение в степень и другие неподдерживаемые операции
  в проверяемом условии дают `unknown`.
- Контракт задаётся inline-объектом со стрелочными предикатами, содержащими
  выражение. На функцию допускается один контракт. Вызовы разрешены внутри
  возвращаемых выражений; вызываемая функция должна иметь контракт.
  Вызовы в условиях `if` и `?:`, выражении выбора и метках `switch`, предикатах контрактов
  и аргументах других вызовов не поддерживаются.
- Проверяется граф модулей, достижимых из входного файла. Поддерживаются
  относительные named imports, re-exports и aliases функций. Внешние runtime-пакеты,
  default/namespace value imports и циклы модулей не поддерживаются.
- В проверяемых зависимостях нельзя совмещать `bigint` и `number`.
  `string` можно сочетать с `number`, но пока нельзя с `bigint`.
  Непрозрачные параметры не мешают независимому условию, но зависимость
  от них даёт `unknown`. Тестовый режим поддерживает графы `bigint` либо
  `string`/`number` и отклоняет непрозрачные типы.
- Для `string` поддерживаются литералы, шаблоны без подстановок, `===`, `!==`,
  `string + string` и `.length`, в том числе в аргументах внутренних вызовов.
  Длина считает кодовые единицы UTF-16: `"😀".length === 2`.
  Индексация, методы строк, регулярки, сравнения `<`/`>` и неявные преобразования
  пока не поддерживаются. В сигнатурах нужен `string`, без literal types и unions.
- Деление `bigint` отбрасывает дробную часть: `-7n / 3n === -2n`.
  В проверяемых зависимостях делитель должен быть ненулевым на каждом пути,
  где вычисляется деление. Используйте `requires: (x, y) => y !== 0n`, ветвление
  или короткое замыкание. Возможный нулевой делитель даёт
  `unknown/unsupported-dependency`, а исчерпание лимита solver — `unknown/solver-unknown`.
  В `requires` ставьте защиту перед делением: `y !== 0n && x / y > 0n`.
  Проверка остаётся выборочной и не доказывает отсутствие исключений в неиспользуемом коде.
- Деление `number` использует округление binary64: `1 / 0 === Infinity`,
  `1 / -0 === -Infinity`, а `0 / 0` даёт `NaN`. Исключать ноль не требуется.
- `number` включает NaN, Infinity и оба знака нуля. Если нужны ограничения
  на входы, задавайте их в `requires`. В JSON `bigint` хранится строкой вроде
  `"123n"`, а `number` — объектом с точными битами или маркером NaN.
- Строки в JSON имеют вид `{ "kind": "string", "value": "текст" }`,
  сохраняющий NUL и одиночные суррогаты. Строковый отчёт использует
  `string-utf16-number-binary64`, регрессии — manifest v3 с типами сигнатур.
  Прежние v1/v2 остаются совместимыми. Если строковый контрпример превышает
  65536 кодовых единиц на аргумент, результат — `unknown`; область доказательства
  этим лимитом не ограничивается.
- Слабое постусловие вызываемой функции может дать `unknown`; найденная
  абстрактная модель не считается подтверждённой ошибкой. По умолчанию
  каждый запрос к Z3 ограничен 5 секундами. Условия с умножением и делением
  могут исчерпать этот лимит и вернуть `unknown`; поддержка операции не гарантирует
  получение доказательства.

Доказательства предполагают, что реальные аргументы соответствуют объявленным
TypeScript-типам. Проект поддерживает ограниченное подмножество языка;
тесты не являются формальным доказательством корректности самого верификатора.
Для строк проверяется нормальное завершение; ограничения памяти и предельный
размер выделяемой строки конкретного JS-движка не доказываются.

## Сборка с Vite

Плагин `ts-value-proof/vite` для Vite `^8.3.8` проверяет выбранные TS-модули
при production-сборке и удаляет вызовы контрактов, предикаты и зависимости API
из исполняемого JS. Исходные файлы остаются без изменений. Пакет пока
устанавливается из локального tarball; [инструкция и пример конфигурации](vite.md).

Укажите `valueProof({ entries: ["src/math.ts"] })` в `plugins` Vite.
Пути считаются от Vite root. Проверяется только выбранный граф поддерживаемых
TS-модулей, а не весь frontend. При `refuted`, `inconsistent`, `unknown` или
ошибке исходников сборка останавливается. Build watch перепроверяет изменения;
dev server не запускает проверку и не удаляет контракты. Source maps могут
содержать исходные контракты, хотя в исполняемом JS их нет.

Отдельная команда `npx ts-value-proof verify src/math.ts` использует то же ядро
и работает без Vite. Внешние вызовы по-прежнему должны соблюдать `requires`.

```sh
npm run typecheck    # проверка типов
npm test             # полный набор проверок, включая типы и runtime-тесты
npm run test:runtime # только runtime, replay и property-based тесты
```
